SAS + Databricks

Bring the lakehouse into Viya.

This project is a live demo and design concept for moving Databricks data into a SAS Viya environment, landing it in a CAS library, and preparing it for analytics and model workflows.

Databricks source
SAS Viya target

The main idea is simple: keep data in the lakehouse, use SAS to understand and process it, then expose the data in a caslib-ready format for downstream work.

The core flow

01

Databricks stores the source tables and business data.

02

SAS connects to the Databricks endpoint using a supported pattern.

03

The data is loaded into a CAS library for analytic processing.

04

Profiling, validation, and modeling preparation begin in Viya.

Why this project exists

Real customers often want to keep a governed lakehouse in Databricks while still making use of SAS Viya, especially for analytics, forecasting, and model development. This repo demonstrates the connection pattern, the data handoff, and the design principles behind the workflow.

What makes it safe

The browser does not hold credentials. The generated SAS snippets illustrate the route, while the actual token or auth configuration is meant to live behind the SAS compute server or a secure enterprise auth layer.

Why CAS matters

CAS is the high-performance in-memory layer used by Viya. By landing data into a CAS library, the project can run validation checks, inspect key fields, and prepare data for a model or a reporting workflow.

What comes next

The next steps are a live connection test, table discovery, quality checks, and a concrete modeling or forecasting use case. This project is the foundation for that flow.

What is being demonstrated

  • Databricks as the source system for operational and analytics data.
  • SAS Viya as the analytics layer that reads, profiles, and transforms the data.
  • CAS as the in-memory landing area for modeling and exploration.
  • Secure system design where secrets are not embedded in the browser or generated code.
This project is a concept and demo for a Databricks-to-Viya analytics pattern. It is designed to make the architecture easier to understand before a production implementation is built.
